### Fixed
- **The test suite silently depended on `python -m pytest`'s cwd-on-`sys.path` behavior, not on any explicit pytest configuration** — invisible locally (every session's own verification ran via `python -m pytest`), but this project's own first-ever real CI run (triggered by Phase 10's push, itself a `pytest -q` invocation without the `-m` form) failed immediately at collection: 9 test modules doing `from tests.<pkg>.conftest import ...` (a pattern established in Phase 8 and reused since) raised `ModuleNotFoundError: No module named 'tests'`, because a bare `pytest` invocation never adds the working directory to `sys.path` the way `python -m pytest` implicitly does. Fixed by adding `"."` to `[tool.pytest.ini_options].pythonpath` in `pyproject.toml`, so the repo root is on `sys.path` for every invocation style, not just the one every session happened to use locally. Verified against the exact bare `pytest -q` invocation CI uses, not just re-confirmed via `python -m pytest`.
- **`_check_no_symlinks_in_chain` (`athena.safety.paths`, a core vault path-traversal defense, P0 security item #1) crashed with an unhandled `PermissionError` on Python 3.12 — the project's own declared minimum and CI-pinned version — for a traversal attempt through an inaccessible ancestor directory** (e.g. `../../../../../../../root/.ssh/id_rsa` run by a non-root process). Root cause: `pathlib.Path.is_symlink()`'s implementation changed between Python 3.12 and 3.13+ — 3.12 lets `PermissionError` propagate from the underlying `lstat()`, while 3.13+'s `os.path.islink()`-based rewrite silently swallows it and returns `False`. This project's dev environment runs Python 3.14, so every prior local "all tests passing" run silently exercised the newer, more forgiving behavior — masking the gap for four phases until CI (correctly pinned to 3.12) caught it for real, immediately after the `pythonpath` fix above unblocked collection. Fixed by catching `OSError` around the `is_symlink()` call and treating an inaccessible ancestor the same way the function's own downstream `resolve(strict=True)` calls already do ("cannot vouch for this path, let it be rejected by the ancestor/escape check instead of crashing") — verified by directly simulating Python 3.12's exact `is_symlink()` semantics via monkeypatch, not just re-run on 3.14 (which would have passed either way and proven nothing). New regression test: `tests/safety/test_paths.py::TestSymlinks::test_permission_error_on_an_inaccessible_ancestor_does_not_crash`.
